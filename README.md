# Chicago Mobility — AAA26 Team Project

Analysis of Chicago taxi trip data for 2024, plus a smart EV-charging RL agent, written up as a Quarto/LaTeX report for the **Advanced Analytics and Applications** course (University of Cologne, Chair IS3).

## 🚀 Getting Started

### 1. Prerequisites

- **[Quarto](https://quarto.org/docs/get-started/)** — publishing system used to render the report.
- **[uv](https://github.com/astral-sh/uv)** — Python package manager.
- **LaTeX** — a TeX distribution (e.g. [TinyTeX](https://yihui.org/tinytex/)): `quarto install tinytex`

### 2. Setup the Environment

```bash
uv sync
uv run python -m ipykernel install --user --name chicago_mobility --display-name "Python (Chicago Mobility)"
```

### 3. Download the Data

Skip this if you just want to run the demo — see the [Demo](#-demo-for-evaluation) section below.

Run in order (each has preconditions described in its script/notebook docstring):

```bash
uv run python scripts/download_taxi_data.py        # → data/raw/chicago_taxi_trips_2024.csv
uv run python scripts/download_community_areas.py  # → data/raw/community_areas.geojson
# then run notebooks/01b_weather_data_preparation.ipynb up to the k-means checkpoint, then:
uv run python scripts/download_weather_data.py      # → data/raw/chicago_weather_hourly.csv
```

## 🧪 Demo (for evaluation)

The real taxi CSV is ~5.3GB / 6.6M rows, so we dont't include it in the repository. For that case, a small **synthetic** demo
dataset is bundled at `data/demo/` (~2,000 fake trips + matching weather,
generated by `scripts/generate_demo_data.py`). It exists purely to prove the
code executes end-to-end — the resulting numbers/plots are not meaningful.

**No setup steps needed.** Just do steps 1–2 above (`uv sync` + install the
kernel) and run the notebooks. `scripts/helpers/datasets.py` automatically
detects that the real CSVs aren't present at their usual paths
and transparently loads the bundled demo CSVs instead, printing a one-line
notice so it's obvious which mode is active:

```
[datasets] taxi: full dataset not found, using demo dataset at data/demo/chicago_taxi_trips_2024_demo.csv
```

**For the team**: set `AAA_FORCE_DEMO_DATA=1` to force demo mode even when
the real data is present locally, e.g. to sanity-check the demo path without
deleting your real data:

```bash
AAA_FORCE_DEMO_DATA=1 uv run jupyter lab
```

### 4. Rendering the Report

Must be run from inside `report/` so Quarto finds `_quarto.yml`:

```bash
cd report && uv run quarto render report.qmd          # PDF (default)
```

Output lands at `docs/report.pdf`.

## 📂 Project Structure

```
data/raw/          Downloaded datasets (taxi trips, weather, community areas, POIs, cached figures)
data/demo/          Bundled synthetic demo dataset, see the Demo section above
notebooks/          Analysis notebooks, see below — run in numeric order
scripts/
  helpers/          Shared modules: datasets.py (loading), preprocessing.py (cleaning),
                     spatial.py (H3/geo utils), modelling.py (panel prep for forecasting)
  download_*.py      One-off data download scripts
report/              Quarto source: report.qmd, sections/, partials/, assets/, references.bib
docs/report.pdf      Rendered final report (submission output)
```

## 📓 Notebooks

Run in this order; later notebooks depend on earlier ones via `scripts/helpers/`.

| Notebook                             | Purpose                                                                                                                                               |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `01a_taxi_data_preparation.ipynb`    | Step-by-step cleaning of the raw taxi trips dataset; logic is encapsulated in `preprocessing.py` for reuse.                                           |
| `01b_weather_data_preparation.ipynb` | Picks representative weather-zone locations via k-means on pickup coordinates, then (after downloading) cleans hourly weather data.                   |
| `01c_poi_preparation.ipynb`          | Fetches and categorises Points of Interest (amenities, shops, tourism, leisure) from OpenStreetMap via `osmnx`.                                       |
| `02_spatial_analytics.ipynb`         | Spatio-temporal demand analysis: H3 hexagon discretization, demand choropleths, OD flows, GMM hotspots.                                               |
| `03a_feature_engineering.ipynb`      | Builds the model-ready demand panel (hexagon × time-bucket, zero-filled) with calendar, weather, and POI features; shared by both forecasting models. |
| `03b_svm.ipynb`                      | Support Vector Regression model forecasting pickup demand per hexagon/time-bucket.                                                                    |
| `03c_nn.ipynb`                       | Feed-forward neural network forecasting the same target, for direct comparison with the SVM.                                                          |
| `04_smart_charging_RL.ipynb`         | Deep Q-Network agent that learns EV smart-charging decisions under stochastic energy demand.                                                          |

All notebooks load data via `scripts/helpers/datasets.py` (`load_taxi_data`, `load_weather_data`, `load_poi_data`, etc.) rather than reading CSVs directly in the notebooks.
